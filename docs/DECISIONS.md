## 하네스 선택 근거

이전 작업 **Plugin and Skill Requirements** (ID `6aaf243e-4354-8342-ac4c-d8e0a16d4269`)에서 OMX 우선 검토·프로젝트 범위 설정이 추천되었으며 Ouroboros는 대안이었다. 현재 사용자는 Windows 기준으로 재검토·선택·설치를 위임했다.

OMX 0.21.5를 `tools/omx`에 설치했다. Node 24에서 버전 명령이 작동한다. tmux 기반 팀 실행은 필수로 사용하지 않는다. 현 Codex 세션이 모델 실행을 맡고 OMX는 프로젝트 목표·ledger·checkpoint를 관리하는 구성을 우선한다. 별도 CLI 모델 실행은 `codex login status`가 미로그인으로 나와 미검증이다. 연속 실행이나 자동 재시작 준비 완료로 발표하지 않는다.

Ouroboros의 공식 Codex 가이드는 Windows 네이티브를 실험적 경로로 표시하고 MCP 서버·사용자 설정 등 추가 구성을 요구한다. 현재 Windows와 프로젝트 한정 설정, 준비 시간 기준으로 OMX를 먼저 검증한다. 어떤 후보도 이름만으로 무중단 실행을 보장하지 않는다.

## 환경 점검에서 발생한 실패·복구

- Git 저장소 아님: 기존 구현/커밋 없음으로 기록. 저장소 초기화와 첫 체크포인트는 준비 대상.
- GitHub CLI: 인증 없음. 관리자 비활성 GitHub 플러그인 설치를 우회하지 않고 공개 문서 조회로 조사.
- npm 메타데이터 조회: 사용자 캐시 경로 EPERM. 프로젝트 `ops/cache/npm` 경로로 바꾸어 메타데이터 조회와 승인된 하네스 설치 성공.
- WSL 배포판 조회: E_ACCESSDENIED. WSL 사용 가능으로 가정하지 않고 Windows 네이티브로 점검.
- 번들 Python 콘솔 한글 표시: 기본 출력 인코딩으로 깨짐. UTF-8 파일 내용은 정상이며 `python -X utf8`로 재출력 확인. 원본 변경 없음.
- 이전 작업 읽기 요청에서 turnLimit 12 거부: 허용 한도 10 이하로 재요청하여 확인.

## 2026-09-21 Supabase·Provider·로그인 추가 지시

사용자가 Supabase DB를 명시하여 이전 미확정 결정을 대체했다. 기본 로그인·세션과 Provider 설정 화면을 범위에 추가했다. 사내 SSO/LLM 공급자 질문에 사용자는 추후 결정하며 구현 기능만 보여주면 된다고 답했다. 따라서 실제 기업 연결은 이번 합격 조건에서 제외하고 설정/미설정 안내를 검증한다. 운영진 API 키의 실제 호출 검증은 별도로 유지한다. 복잡한 조직 권한은 후순위지만 기본 사용자 소유권/RLS는 로그인 기능과 함께 구현한다.

스킬 파일·로컬 enabled 설정·카탈로그 연결·실제 실행을 구별해 다시 기록했다. 별도 CLI 인증과 밤샘 실행은 여전히 미검증이다. 기존 brief와 원기록은 보존하고 변경은 OMX 지원 steering 명령으로 기록한다.

## 16:42 이후 최신 결정

사용자는 Vercel을 필수로 두지 않고 GPT Sites도 허용했다. DB는 이미 생성한 Supabase 프로젝트 `wsziosnttnxefgfbgpeq`를 사용한다. 사용자는 ChatGPT에 Supabase 계정을 연결했다고 설명했다. 다만 현재 Codex 도구 목록에는 Supabase 관리 도구가 없고 연결 카탈로그 재조회도 DISABLED_BY_ADMIN/NOT_AVAILABLE이므로, 이 세션에서 실제 프로젝트 접근 성공을 주장하지 않는다. 프로젝트 ID는 비밀키가 아니며 키 값은 요구하거나 기록하지 않았다.

GPT Sites building/hosting 스킬을 확인했다. Sites의 서버 배포 계약은 Worker 호환 JavaScript 산출물이며 Python FastAPI를 그대로 배포하는 경로로 가정할 수 없다. 제품 구현 시 기존 문서 파서와 서버 기능을 실제 지원하는 호스팅 경로를 선택한다. Sites를 선택하면 서버 처리 경로까지 검증해야 하며 정적 화면만 배포해 완료 처리하지 않는다. Vercel 관련 아래의 제약은 해당 호스팅을 선택할 경우에 적용한다. 이번에는 추가 호스팅 설치·사이트 생성보다 승인된 문서 처리·검증 환경 설치를 우선한다.
