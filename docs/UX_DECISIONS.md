# RE:Build Agent UI 계약 — 06

2026-09-21 최신 사용자 수정 반영. 이전 의사결정은 ops/checkpoints의 UI 06 이전 사본에 보존했다. GOAL 원문은 수정하지 않았다.

## 구조와 표현

좌측 메뉴: 프로젝트 / 지식조회 / 지식 자료실 / 데이터 관리 / 표준 양식 / 설정. 공식 제품명은 RE:Build Agent이며 지식조회는 기존 챗봇의 새 명칭이다. Search Mode와 AI Insight Mode는 같은 화면의 탭으로 유지한다. 질의와 프로젝트 맥락을 보존하며 미연결 AI를 실행 결과처럼 표시하지 않는다.

차콜 본문, 절제된 그린 강조, 흰 작업면, 일관된 여백과 선형 SVG 아이콘을 사용한다. UI/UX Pro Max의 Minimalism/Swiss 기능 중심 원칙과 접근성 지침을 적용했다. 랜딩 페이지용 Hero/CTA 권고는 업무 화면 구조에 적용하지 않았다. 한글은 프로젝트 범위에 설치한 Pretendard 1.3.9를 로컬 제공한다. OFL-1.1 원문과 저작권 고지를 포함하며 외부 폰트 CDN 요청은 없다.

## 프로젝트와 업로드

새 프로젝트 창은 프로젝트 이름 → 파일 선택/드래그 → 선택 파일 확인/제거 → 프로젝트 생성 순서다. 파일은 나중에도 추가할 수 있다. 지원하지 않는 형식은 알려주고 제외한다. 문서 대상이 없는 상태로 자료를 다른 프로젝트에 귀속시키지 않는다.

프로젝트 내부에는 자료 확인/추가와 ITB 분석표, 심의장표, Risk Register를 유지한다. 초안 → 원문 근거 → 검토 의견 수정 → 확인 체크 → 승인 흐름을 체험할 수 있다. 수정과 입력 추가는 기존 승인/초안을 무효화한다. 현재 시안은 파일명·크기와 브라우저 메모리의 검토 상태만 다룬다. 새 파일을 저장·분석했다고 표시하지 않고 N01 제공 자료의 예시 초안을 명확히 구분한다. 실제 결과물 생성 버튼은 연결 전 상태다.

## 지식 자료실

목록/관계 보기 토글을 제거한다. 페이지 상단에 기본 지식 연결 노드를 표시하고, 하단에 선택한 항목의 과거↔신규 비교·연결 이유·적용 한계·다음 검토·양쪽 원문을 함께 제공한다. 이 UI의 연결은 제공 원문에서 확인한 P01과 N01 조건을 위한 예시다. 사용자 임의 신규 업로드와 자동 연결된 것으로 표시하지 않는다.

세 연결: 담수/염수 처리 조건, 과거 28일/신규 승인 14일 통지기한, 과거 관측 유입량/신규 방류 허용량과 설계값 미확정. 각 노드 선택은 해당 설명을 바꾸고 원문 근거 패널을 통해 정확한 파일과 locator를 확인할 수 있다. 관계 거리·선 굵기를 유사도나 위험 점수로 표현하지 않는다. 향후 제품 구현에서는 새 입력에서 이 구조를 실제로 생성하고 관련 없음도 그대로 보여줘야 한다.

## 데이터 관리

핵심은 축적된 과거 자료의 규모와 구성을 확인하는 것이다. 제공 INPUT을 실제 집계한 과거 프로젝트 15개, 원본 155개, 신규 자료 18개, 양식 7개를 표시한다. 수치는 Supabase 등록 수가 아니며 제공 폴더 기준임을 명시한다. 프로젝트별 문서 수·파일 형식·전체 문서 목록과 새 유입 자료를 탐색한다.

표현은 새로 유입된 문서로 통일한다. 실패/처리중 KPI와 등록 대상 섹션은 제거한다. 실제 변환 오류를 숨기거나 성공으로 꾸미는 것은 아니며, 제품 연결 시 필요한 오류 안내는 해당 문서 작업에서 제공한다. 수동 업데이트의 폴더 선택 → 자료 범위 확인 → 승인 원칙은 별도 대화상자에서 유지한다. 미연결 상태에 녹색 최신 판정을 표시하지 않는다.

## 양식과 세 결과물

실제 경로: data/REBUILD_INPUT_v1/REBUILD_INPUT_v1/03_OUTPUT_TEMPLATES. 입력에서 부른 단수 폴더명과 달리 실제 디렉터리명은 복수형이다. ITB_Analysis_Template.xlsx, Risk_Register_Template.xlsx, Review_Deck_Template.pptx를 기본 양식으로 표시하고 계약 검토서·심의 요약서·교훈 정리서·프로젝트 비교표까지 전체 7종을 원본 다운로드로 제공한다. 복사본과 원본 SHA-256이 같아야 한다. 양식 버전 선택/승인 보호는 제품의 필수 기능으로 유지한다.

ITB: 주요 항목의 값·단위·개정과 과거 이슈 링크, 상세 비교 8열을 보존한다. Risk Register: 위험·조건·강도·과거 프로젝트·대응·양쪽 근거를 제공한다. 근거 없는 강도·발생가능성·영향·점수는 빈칸과 검토 필요다. 독립 사례/동일 척도/표본 수 검증 없이 최빈값을 확정하지 않는다. 심의장표: 사업 개요/ITB 조건/과거 적용성/위험 대응/미확정 의사결정의 실제 5장 구성을 유지한다.

## 변경하지 않은 경계

제품의 기본 기능(원본 보존, 승인 후 기존 폴더 지식화, 신규 업로드, 정확한 변환과 SourceRef, 실제 Supabase/OpenAI 연결, 사용자 권한, 검토·승인 후 파일 생성)은 유지한다. 원본 자료와 최초 HTML 목업을 수정하지 않는다. 이번 UI 승인이 제품 전체의 기능 완료나 배포 승인은 아니다.

## 실제 장표 렌더링에서 확인한 분량 계약 (2026-09-21)

PPTX의 5장 구성과 XML 내용 보존은 화면 가독성을 보장하지 않았다. 실제 제공 자료로 생성·렌더링한 결과 본문과 전체 SourceRef를 짧은 원본 placeholder에 함께 출력하면 겹침과 잘림이 발생했다. docs/OUTPUT_REVIEW.md에 실패를 보존한다.

심의장표의 생성 본문은 근거 기반 원문 발췌임을 명시한다. 전체 비교·미확정 정보·위험 강도 근거와 SourceRef는 상세 보기 및 발표자 노트에 보존하고, 화면에는 짧은 출처 링크와 전체 근거 수를 제공한다. 사용자가 수정한 본문·판단·검토 의견은 표시 한도 안에서 그대로 출력하며, 초과하면 수정 안내와 함께 저장·승인을 거부한다. 전체 근거 삭제나 허위 AI 요약으로 분량을 줄이지 않는다. 생성 사본의 배치와 제품 메타데이터를 고치며 제공 양식 원본은 변경하지 않는다.

새 계약의 완료 근거는 실제 P01/N01 및 경계 분량 장표 렌더링, 내용·노트·링크 재열기, 승인본 보존 회귀를 모두 확인한 뒤 기록한다. 현재 구현 과정의 결정이며 이 문단 자체는 PASS 증거가 아니다.
