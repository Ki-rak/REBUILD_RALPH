2. 입력·분석·결과물
   기존 폴더는 대상 확인·사용자 승인 후 지식화하고 신규 업로드는 원본 보존 후 MD·JSON으로 자동 변환한다. 해시·파일명·개정·승인 상태, 표·수치·단위·수식·캐시값과 페이지·셀·문단·슬라이드 위치를 보존하고 중복·변경 버전·변환 실패를 처리한다. 신규 조건과 실제 과거 자료로 적용성·위험을 판단한다. 승인 정정서는 변경 조항만 대체하며 미승인 최신본·이메일로 유효 계약을 덮어쓰지 않는다. 과거 관측값과 신규 설계값, 허용량과 설계량, 미확정과 0, 비용과 수입을 구별한다. 부족·상충은 REVIEW\_REQUIRED다.
   제공 양식의 ITB 분석표 XLSX에 주요 정보·과거 이슈 trigger·근거 링크를 구현한다. 이어 Risk Register XLSX·5장 심의장표 PPTX도 완성한다. 리스크는 명칭·원인/조건·과거 프로젝트·대응방안·출처를 포함한다. 강도는 충분한 비교 가능 독립 사례의 후보·표본 수·분포를 제시하고 부족·동률·척도 불일치는 빈칸·검토 필요다. 빈도≠확률이다. 심의장표는 사업 개요·ITB 조건·과거 적용성·위험 대응·미확정 의사결정을 담는다. 모두 초안→근거→사용자 수정·검토·승인→편집 가능한 파일 생성 흐름을 갖춘다. 입력·근거·초안·양식 변경 시 관련 승인을 무효화한다.

3. 실제 서비스와 AI 인증
   Supabase 프로젝트 wsziosnttnxefgfbgpeq의 실제 DB·Storage·Auth를 연결하여 영속 저장·복원, 로그인·세션·로그아웃과 사용자별 DB/파일 접근 제어·RLS를 검증한다. 기존 데이터는 보존하고 추가 스키마·정책은 이력·복구법을 남긴다.
   AI 호출은 로컬 개발·로컬 데모=공식 Codex SDK/CLI의 ChatGPT OAuth, 배포용 서버=OpenAI API key로 실제 분리한다. server/ai를 검토·보완하여 제품 분석에 연결한다. 로컬은 공식 로그인·최소 권한 전용 환경을 사용하며 API key로 조용히 전환하지 않는다. OAuth 토큰을 추출·복사하거나 브라우저·DB·로그·배포로 보내지 않고 개인 구독의 공개 프록시 제공은 금지한다. 배포는 서버 OPENAI\_API\_KEY·OPENAI\_MODEL과 [https://api.openai.com/v1만](https://api.openai.com/v1만) 사용한다. OPENAI\_BASE\_URL의 임의 주소·OAuth 전환은 거부한다. .env는 비밀 파일, .env.example은 빈 템플릿으로 유지하고 Git에서 제외한다. 두 경로의 실제 성공 호출·근거를 검증하고 오류·시간초과·한도는 통제된 시험으로 검증한다. Provider 설정에 실행 환경·인증 방식·모델·연결 상태를 표시한다. 모델이 미연결이면 제한을 표시하고 규칙·예시·사전 생성 결과를 실시간 AI로 표현하지 않는다. 사내 LLM·SSO는 설정 화면과 미설정 안내만 포함하고 실제 회사 연동은 제외한다.
